test: end-to-end pipeline verification against a local mock upstream

Adds test/e2e.test.ts, which runs the real core services and the real tool
registration against an in-process OpenAI-compatible mock server. This is the
strongest verification available without the user's credentials and without
restarting the DSH profile.

Three cases, all green:
1. analyze -> plan -> VPA -> generate. Asserts the normalized analysis, the
   style guide surviving planning, the generated bytes round-tripping exactly,
   the section pointing at its image, the project reaching EDITING, and that
   /chat/completions was called for analysis + planning + VPA.
   Also pins a real upstream detail: with a reference image present the
   reference-guided path uses /images/edits, not /images/generations.
2. Version semantics: a second generation produces v2 without touching v1, both
   files stay on disk, exactly one version is active, and activating v1
   repoints the section while still keeping v2.
3. The tool layer: create_project -> analyze -> plan -> generate_section through
   the real registerMxpageTools, asserting a DSH attachmentId comes back with
   real bytes AND the same bytes exist on disk under the workspace root.

Also confirmed by these tests: defineTool validates arguments at execute time
(a camelCase projectId is rejected with ToolArgsError), and a channel that
declares its models explicitly skips GET /models discovery as designed.

Full suite: 40 tests, 40 pass. tsc --noEmit: 0 errors.
